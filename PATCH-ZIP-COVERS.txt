COSA CAMBIA
- 228 cover full + 228 thumb non sono piu' pubblicate come 456 WebP separati.
- Sono contenute in 18 ZIP_STORED: 9 full e 9 thumbs, blocchi da 50 VIN.
- Il browser scarica solo il pacchetto necessario e lo tiene in cache in memoria.
- Nessuna dipendenza esterna: il lettore ZIP e' in assets/js/records-cover-archives.js.
- record-covers.js continua a usare i vecchi percorsi logici assets/covers/full/... e thumbs/....

PER APPLICARE LA PATCH
1. Copia/sovrascrivi i file del pacchetto patch mantenendo le stesse cartelle.
2. Assicurati che assets/covers/packs/full e assets/covers/packs/thumbs siano caricati.
3. Per ottenere davvero la riduzione del numero di file, elimina dal repository:
     assets/covers/full/
     assets/covers/thumbs/
   Se li lasci, il sito funziona comunque: restano soltanto file inutilizzati.
4. Pubblica/commit come al solito su GitHub Pages.

ATTENZIONE SE USI SOLO IL BROWSER DI GITHUB
"Upload files" aggiunge/sovrascrive ma non elimina automaticamente i vecchi WebP.
Quindi la patch funziona anche senza cancellarli, ma la riduzione da 456 file a 18
archivi si ottiene soltanto rimuovendo una volta le due vecchie cartelle.

PROVA LOCALE
Le cover dentro ZIP richiedono HTTP. Il doppio click su dischi.html/collezione.html
(file://) non e' una prova affidabile. Dalla cartella del sito puoi usare:

  python -m http.server

poi aprire l'indirizzo locale mostrato dal comando. Su GitHub Pages non serve nulla.

AGGIUNGERE/SOSTITUIRE COVER IN FUTURO
Metodo automatico (richiede Pillow):
  python tools/prepare_cover.py cover.jpg --id VIN-0434 --artist "Artista" --title "Titolo"

Oppure, con WebP gia' pronti:
  assets/covers/staging/full/VIN-0434.webp
  assets/covers/staging/thumbs/VIN-0434.webp
  python tools/cover_packs.py --clear-staging

I pack vengono riscritti mantenendo le cover gia' presenti. WebP e' gia' compresso,
percio' gli archivi usano ZIP_STORED e non tentano una seconda compressione.
